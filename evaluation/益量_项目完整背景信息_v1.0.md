## 2. 制度与政策事实（F）

**政府购买服务的基本逻辑**

财政部《政府购买服务管理办法》明确：将适合市场化方式提供的公共服务交给符合条件的供应商，按**服务数量和质量**等因素支付费用，并受预算约束与绩效管理要求。（[财政部，2020][mof]）

由此，购买方关注的不只是“是否发生服务”，还包括能否说明**做了什么、做到什么程度、依据何在**。

**特殊困难老年人探访关爱**

国务院相关部门指导意见要求，通过上门、电话、视频等方式了解老年人生活状况，并视需要开展政策告知、安全风险发现、生活与健康需求识别、需求转介、必要救援及后续专业服务衔接等。（[中国政府网，2022][gov-visit]）

政策所指对象包括独居、空巢、留守、失能、重残、计划生育特殊家庭等老年人。（[中国政府网，2022][gov-visit]）

指导意见同时要求注意特殊困难老年人**隐私保护**。（[中国政府网，2022][gov-visit]）

## 3. 服务现场：一次探访实际可能包含什么（F）

政策与实务语境下，单次探访可能涉及的信息与动作包括但不限于：

- 健康、生活、安全、情绪及实际服务需求等了解情况；
- 发现风险或需求后的**记录**；
- 向社区、家属、医疗、养老、社工等主体的**转介或衔接**；
- 后续是否跟进、是否闭环。

这与管理层常见汇总口径之间可能存在距离。例如汇总层常出现：

```text
完成探访 N 次 · 服务时长 · 照片/签到
```

而现场链条可能是：

```text
上门 → 发现需求/风险 → 记录 → 转介 → 跟进 → （是否处置/结果）
```

**F**：政策要求探访包含识别、转介、衔接等环节。  
**H**：上述“汇总口径与现场链条之间的距离”在具体机构中是否构成显著管理负担——**待访谈验证**。

## 4. 政府购买与验收：场域中存在的管理链条（F）

在政府采购语境下，典型管理顺序为：

```text
预算与购买 → 供应商实施 → 过程记录 → 评价/绩效 → 验收与拨付
```

购买方验收材料通常需要能对应：**服务量、服务质量、过程可追溯性**等维度（具体表单因地区、项目而异）。

**F**：政府购买强调数量、质量与绩效。  
**H**：服务机构在整理验收材料时的耗时、返工率、字段缺失等问题——**待访谈验证**，不可写成已证实的行业普遍事实。

## 7. 场域中的角色（描述“谁存在”，不预设产品使用者）

| 角色 | 在探访关爱项目中的位置 | 与本选题相关的常见关切（场域描述，非产品需求） |
|------|------------------------|-----------------------------------------------|
| **服务对象** | 政策所指特殊困难老年人 | 接受探访与服务衔接；个人信息敏感 |
| **一线服务人员** | 社工、养老服务员等 | 执行探访、发现与记录、发起转介、配合跟进 |
| **项目主管/督导** | 机构内管理岗 | 任务分配、进度掌握、材料完整性、阶段汇总与验收准备 |
| **社区工作人员** | 属地协同方 | 需求转介、资源衔接的一环 |
| **购买/管理主体** | 街道、民政等 | 覆盖、履约、成果与证据、合规与拨付（**是否使用某类数字化工具：H，未验证**） |
| **潜在资金提供方（场域层面）** | 政府购买资金、基金会、企业 CSR 等 | 存在多种可能；**谁为“改善记录与验收效率”付费：H，未验证** |

**H**：购买方、管理方、服务机构、一线人员的目标函数是否一致——**待访谈**（与测试用冲突约束相关，见另册）。

## 8. 现行工作方式（模拟机构情景，H 待访谈印证）

项目组**假定**第一家模拟试点机构目前大致采用以下组合（**机构个案情景，非已验证的行业普遍做法**）：

| 环节 | 常见做法（假定） |
|------|------------------|
| 服务前 | 名单下发 → 任务安排 → 分配给一线人员 |
| 服务中 | 上门/电话/视频探访；了解健康、生活、安全、情绪、服务需求 |
| 发现问题 | 居家安全、生活照料、医疗康复、精神慰藉、政策申请、紧急情况等 |
| 转介 | 联系社区、家属、养老/医疗机构、社工专业服务等 |
| 后续 | 需知晓是否接收、是否处理、处理时间、是否再次跟进 |
| 资料载体 | Excel、Word、微信、图片、纸质或电子服务记录表、月报/阶段总结等**分散存放** |

**H**：资料是否因分散而导致主管汇总、验收整理困难——**核心待验证假设**。  
**H**：转介与跟进是否有统一状态记录——**待访谈**。

## 9. 场域中的三类结构性问题（问题描述，不含解决方案）

以下用**管理语言**描述缺口，不指向任何产品形态。

### 9.1 活动记录与“可说明的成果”之间可能有距离

| 能较直接记录的（活动层） | 往往需要额外说明的（产出/结果层） |
|--------------------------|-----------------------------------|
| 探访次数、联系次数、服务时长 | 发现了哪些需求/风险 |
| 签到、照片 | 转介了多少、谁接收 |
| | 哪些已处理、哪些仍待处理、哪些无法解决 |

**F**：政策要求识别、转介、衔接。  
**H**：机构是否因口径停留在“次数/时长”而在验收时难以回答产出与闭环问题——**待验证**。

### 9.2 证据可能分散在多个载体

若需求发现、沟通记录、照片、表格、转介记录分属不同渠道，则阶段性整理可能需要**人工对齐、补字段、重抄**。

**H**：该问题在模拟机构情景中的严重程度（频次、耗时、最易出错的环节）——**待 5 次访谈验证**。

### 9.3 “发现问题”与“问题被处理”可能不是同一事实

```text
探访中记录了某风险  ≠  该风险已被处置或需求已满足
```

管理上有必要区分：**发现 → 转介 → 跟进 → 当前状态**是否可追溯。

**F**：政策要求转介与衔接。  
**H**：现有做法能否快速判断闭环状态——**待访谈**。

## 13. 优先通过访谈澄清的问题（研究议程，非方案）

建议 5 次访谈覆盖：一线社工 ×2、项目主管 ×1、街道/社区管理者 ×1、基金会/公益项目或相关专家 ×1。

| # | 问题 |
|---|------|
| 1 | 当前项目如何记录探访与转介？ |
| 2 | 验收需提交哪些材料、由谁整理？ |
| 3 | 哪一环节最耗时、最易返工？ |
| 4 | 转介是否需要追踪状态？现在如何追踪？ |
| 5 | 现有软件/表格能否满足需求？卡在哪里？ |
| 6 | 若增加记录字段，一线可接受的额外负担上限？ |
| 7 | 谁对“材料质量”负责？谁对“服务执行”负责？ |
| 8 | 若存在付费可能，谁更可能承担成本？ |
