## 0. 为什么要先冻结「测试世界」

V1fix-A 暴露的最大问题之一，不是 Agent「不会答」，而是**多轮后事实漂移**：

| 漂移类型 | V1fix-A 中的表现 | 冻结后要杜绝 |
|----------|------------------|--------------|
| 付费方漂移 | 有的轮次变成老人自费、有的变成基金会 | 付费方固定为**街道政府购买** |
| 产品形态漂移 | 出现语音客服、老人微信端、志愿者匹配 | MVP 固定为**探访员台账 + 异常转介 + 验收汇总** |
| 数字编造 | Agent 自行给出市场规模、单价、覆盖率 | 数字只来自本文 **公开层** 或 **隐藏包 P1–P12** |
| 范围膨胀 | 助餐、智能硬件、全区推广同时出现 | 一期只做**单街道探访验收**，助餐仅作远期扩展 |

**原则**：学生（模拟用户）**只知道公开层**；Agent 问对了才给对应隐藏包；问错了就给「暂无新信息」。

## 2. 益量 v0.1 立项假设（公开层）

> **用途**：YL-L 第 1 轮、YL-G 开场、YL-R 材料摘要。  
> 模拟学生**可以主动说**这些内容；**不应**包含隐藏包数字。

### 2.1 项目卡片（公开）

```text
我们是「益量」项目组，4 人，参加挑战杯社会治理赛道。

想做一个面向街道和社区养老服务机构的工具，帮助政府购买的「居家探访」项目在验收时：
把各机构分散的探访记录统一口径，形成过程台账和结项汇总，方便材料核验，
也能为下一周期预算测算提供可比的单位成本依据。

一期不做老人预约 App，也不做志愿者匹配；聚焦探访任务的记录、异常转介和验收导出。

目前只有初步想法，做过 1 次街道养老科室的简短交流，还没有正式试点数据。
```

## 3. 隐藏信息包 P1–P12（仅追问命中时释放）

> **.harness 规则**：语义匹配 ≥ 阈值才释放对应包；匹配失败则回复：  
> 「我这边暂时没有更具体的数据，目前还是初步想法阶段。」  
> 并标记 `question_response_mismatch=true`。

### P1 · 试点范围与行政区

**触发问法示例**：试点在哪里、覆盖多大范围、哪个街道  
**释放内容**：

```text
我们设想先在东部某市的「清澜街道」试点。街道辖区户籍老人约 1.15 万人，
其中纳入政府重点探访清单的约 320 人（独居、空巢、高龄独居为主）。
一期不跨区推广，只做这一条街道。
```

### P2 · 服务频次与政府要求

**触发问法示例**：多久探访一次、政府合同要求频次  
**释放内容**：

```text
街道对重点对象的最低要求是每月至少上门探访 1 次，每次有效服务时长不少于 20 分钟。
节假日另有应急电话随访要求，但一期系统可以先只做「月度上门」台账。
```

### P3 · 合同金额与付费结构

**触发问法示例**：项目多少钱、谁付钱、预算从哪来  
**释放内容**：

```text
付费方是街道，资金来自区级「政府购买养老服务」专项。
本年度居家探访服务包合同额约 24 万元（含税），按季度拨付给中标机构，
街道养老科室按验收材料审核后付款。不向老人收费。
```

### P4 · 承接机构与服务供给

**触发问法示例**：谁来做探访、几家机构、怎么分工  
**释放内容**：

```text
街道通过购买服务委托 2 家社区养老服务中心承接探访。
A 机构负责清澜东片约 180 人，B 机构负责西片约 140 人。
每家机构有 3–4 名专职探访员，另有站长负责台账汇总。
```

### P5 · 现状工具与痛点实例

**触发问法示例**：现在怎么记录、用什么系统、痛点是什么  
**释放内容**：

```text
现在没有统一系统：探访员微信群发照片+定位，站长月底手工填 Excel。
两家机构 Excel 字段不一致（比如 A 用「服务时长」，B 用「入户分钟数」；
异常事件 A 记「备注」，B 记「风险标签」）。
街道验收时要花 2–3 周对账，还经常因缺字段退回补材料。
```

### P6 · 街道访谈反馈（需求侧原话）

**触发问法示例**：街道怎么说、他们最关心什么  
**释放内容**：

```text
街道养老科室负责人说：「我们不缺探访本身，缺的是验收时一眼能看懂的台账。
最好能看到哪家机构、哪个月、哪类对象、单次成本大概多少，
异常有没有跟进闭环。你们要是能按我们去年的验收表格式导出，我们最省事。」
```

### P7 · 团队构成与已有资源

**触发问法示例**：团队谁负责什么、有什么基础  
**释放内容**：

```text
4 人：1 人公共管理（懂政策）、1 人软件（后端）、1 人产品/UX、1 人财务测算。
学校创新创业实验室可提供测试服务器；无政务外网部署权限。
认识 1 名清澜街道养老科室科员（访谈对象），无正式合作备忘录。
```

### P8 · 合规与能力边界

**触发问法示例**：医疗、资质、隐私、能不能诊断  
**释放内容**：

```text
我们不做医疗诊断、不替代 120/急救指挥。
系统只记录探访员勾选的「异常类型」（如疑似跌倒、燃气隐患、情绪异常），
并生成转介工单给街道指定联系人。老人身份信息按街道已有清单导入，一期不做公开招募。
```

### P9 · 替代方案与竞品

**触发问法示例**：现在有什么方案、和别家比有什么不同  
**释放内容**：

```text
街道试过让机构直接用「智慧养老」大平台里的探访模块，但两家机构嫌操作重、
和本机构原有档案系统不打通，最后又回到 Excel。
市面也有 ToG 养老大数据平台，偏大屏展示，对「验收材料导出和单位成本对比」支持弱。
我们想切「轻量台账+验收导出」这条缝。
```

### P10 · 技术部署约束

**触发问法示例**：部署在哪、政务云、数据安全  
**释放内容**：

```text
一期 PoC 计划部署在学校实验室私有化环境，用脱敏样例数据演示；
正式试点需街道信创/政务云评审，预计 6–12 个月后。
因此 MVP 必须支持「离线导出 Excel/PDF 验收包」，不能假设实时政务外网互联。
```

### P11 · 政府验收模板关键字段

**触发问法示例**：验收看什么字段、街道要什么表  
**释放内容**：

```text
街道去年验收表核心字段包括：
服务对象编号、姓名（脱敏）、探访日期、探访员、机构名称、服务时长、
服务内容勾选、异常标记、转介对象、转介回执日期、单次服务成本（元）、佐证材料链接。
缺「转介回执日期」或「单次成本」整行会被标红退回。
```

### P12 · 真实异常闭环案例（证据边界）

**触发问法示例**：有没有真实例子、异常怎么处理  
**释放内容**：

```text
街道提供的脱敏案例（去年）：探访员发现老人家中燃气软管老化，
在微信群发了照片但未按模板登记，街道验收时这条不算有效异常闭环。
另一例：按模板登记后 48 小时内完成燃气公司上门更换，有回执照片，验收通过。
我们希望系统强制「异常 → 转介 → 回执」最小闭环。
```

## 5. MVP 功能边界（公开 + 验收）

### 5.1 一期必做（P0）

| 模块 | 说明 |
|------|------|
| 探访任务台账 | 派单、打卡、时长、内容勾选 |
| 异常标记与转介工单 | 类型枚举 + 指定联系人 + 回执上传 |
| 验收材料导出 | 按 P11 字段导出 Excel/PDF |
| 机构维度成本汇总 | 按机构/月份汇总单次成本，支持街道对账 |

### 5.2 一期不做（出现则记范围膨胀）

- 老人端 App / 小程序预约
- 志愿者匹配、时间银行
- 助餐配送执行与厨房管理
- 可穿戴/摄像头/语音客服
- 全区级大数据驾驶舱
- 医疗诊断或急救调度

### 5.3 二期可扩展（Agent 可提，但须标注「非 MVP」）

- 助餐服务台账（同一验收框架复用）
- 多街道 SaaS 化
- 与区级养老平台 API 对接

## 6. 测试情景与固定提示词

### 6.1 YL-L（课程辅导 · 4 轮固定脚本）

| 轮次 | 模式 | 学生固定发言 |
|------|------|--------------|
| L1 | coursework | 使用 **§2.1 项目卡片** 全文 |

| L3 | coursework | 「街道访谈提到验收台账，但不确定和单位成本对比哪个更应该先做。」 |

**L 轮隐藏包策略**：L1 不给隐藏包；L2 起若 Agent 问 P5/P6 可释放；L3 可释放 P3/P11；L4 不应再新增未问过的数字。

### 6.2 YL-G（项目教练 · 互动场景 · 每 run 最多 8 轮）

**开场（G-R1，每 run 相同）**：

```text
【互动场景】你是项目教练。我们是「益量」项目组。

背景：想做政府购买居家探访服务的验收台账工具，解决记录分散、口径不一、
单位成本难比较的问题。一期不做老人 App。

我们目前只有 1 次街道访谈，还没有试点数据。请先帮我们理清：
1）目标用户到底是谁；2）一期 MVP 最小闭环是什么；3）接下来 2 周最该验证什么。

你可以问我问题，我知道的会回答；不知道的我会说不知道。
```

**模拟用户回答规则**：

- Agent 问题命中 P1–P12 → 释放对应包全文
- 问题模糊 → 「你具体指哪一块？试点范围、预算还是现在怎么记录的？」
- 问题超范围（如全国市场规模）→ 「这个我们还没调研，暂时没有数据。」
- **禁止**模拟用户主动泄露未问过的 P 包

**建议 G run 主题（3 runs，可选其一固定）**：

| Run | 聚焦 | 期望 Agent 在 8 轮内触及 |
|-----|------|--------------------------|
| G1 | 用户与付费方 | P1, P3, P4, P6 |
| G2 | MVP 范围 | P5, P8, P11 + 砍掉助餐/老人端 |
| G3 | 验证计划 | P7, P10, P12 + 2 周可执行实验 |

### 6.3 YL-R（竞赛冲刺 · 独立评审 · 3 轮新会话）

**固定材料摘要（R 轮附件，每轮新 session 粘贴相同）**：

```text
【益量 v0.1 材料摘要】
- 赛道：社会治理和公共服务
- 场景：政府购买居家探访服务验收
- 痛点：记录分散、口径不一、单位成本不可比
- 一期：探访台账 + 异常转介 + 验收导出；不做老人端

- 公开短板：无政务云、无医疗资质

请按挑战杯评审视角：1）用 3 句话概括项目；2）最大风险是什么；
3）若只能保留一个 MVP 功能，你建议保留哪个，为什么。
```

**R 轮不给隐藏包**（测 Agent 在信息不足时是否编造）。
