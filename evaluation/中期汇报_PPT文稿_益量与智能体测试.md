## P3 敲定的项目是什么

| 项 | 设定 |
|----|------|
| **项目名** | 益量（课程工作名，非已注册公司/产品） |
| **参赛方向** | 挑战杯 · **社会治理和公共服务** |
| **关注领域** | 政府购买下的 **特殊困难老年人探访关爱** —— 重点在「服务做完之后，**怎么记录、怎么验收**」，不在「帮老人预约服务」 |
| **中期定位** | 问题场域与测试世界已冻结；**无签约机构、无付费客户、无真实运营数据** |

**益量想做的事（一句话）**  
把机构里分散的探访过程记录，整理成街道验收时能核对的一条 **「探访 → 发现 → 转介 → 跟进 → 材料齐全」** 证据链。

**明确不是**  
老人预约 App · 志愿者撮合/量化志愿时长 · 助餐配送 · 宣称「老人更幸福/医疗费下降」

## P4 问题发生在什么场景（制度与环节）

**制度背景（事实 F）**

- 政府通过购买服务，把探访等工作交给社区机构，按 **数量 + 质量** 付费并要验收（《政府购买服务管理办法》）。
- 探访政策要求：识别需求与风险、**转介衔接**、保护隐私（特殊困难老年人探访关爱指导意见）。

**问题卡在哪个环节**

```text
政府预算 → 机构上门探访 → 【记录 scattered】→ 机构汇总 → 街道验收 → 拨付
                              ↑
                         我们的问题域在这里
```

**现场完整链条 vs 验收常用口径**

| 现场实际（政策语境） | 月底汇总/验收常见口径 |
|----------------------|------------------------|
| 上门 → 发现风险 → 记录 → 转介 → 跟进 → 是否处置 | 探访 **N 次** · 时长 · 照片/签到 |

**核心矛盾**：能证明「去过了」，往往证明不了「发现了什么、转介了吗、闭环了吗、单次成本多少」。

## P5 人群是谁、各自干什么

| 人群 | 身份 | 与问题的关系 |
|------|------|--------------|
| **服务对象** | 独居、空巢、失能等 **特殊困难老年人**（政策界定） | 被探访；不操作任何系统 |
| **一线人员** | 机构社工、养老服务员（**政府购买的专业服务**，非本项目的「志愿者撮合」） | 第一手信息来源；执行探访与记录 |
| **项目主管** | 机构内督导 | 派单、查进度、**拼验收材料**（痛点最可能在这里，待访谈 H） |
| **社区等** | 属地协作方 | 转介与资源衔接的一环 |
| **街道/民政** | 政府购买方、验收方 | 看汇总与证据是否够拨付依据 |
| **我们团队** | 4 名大学生 | 做产品与验证；本学期访谈 **≤5 次** |

**三个主体、三个待验证问题（中期不写死答案）**

- 谁最痛？→ H  
- 谁日常会用工具？→ H  
- 谁可能为工具付费（机构 / 政府 / 基金会）？→ H

## P7 这个场景里具体卡在哪（三类问题）

| # | 问题 | 举例 |
|---|------|------|
| **1** | 活动 ≠ 可说明的成果 | 写了「探访 100 人次」，答不出「发现几个需求、几个转介、几个闭环」 |
| **2** | 证据分散、口径不一 | 微信有图、表上没登记；A 站写「时长」、B 站写「分钟」 |
| **3** | 发现 ≠ 已处理 | 探访时记了燃气隐患，验收时要「转介回执日期」——没有则 **整行退回** |

**街道验收常要字段（模拟机构主管口径，测试用 H06）**  
对象编号、探访日期、服务人员、机构、时长、服务内容、异常标记、转介对象、**回执日期**、**单次成本**、佐证链接。

## P11 测试总逻辑（四句话）

1. **冻结同一个「益量世界」** —— 所有测试共用公开背景 + 同一套隐状态，避免聊几轮项目变样。  
2. **公开层 + 隐状态分层** —— 学生开场只说公开信息；细节 **Agent 问对才给**（见 P12–P13）。  
3. **脚本 + 模拟用户** —— 学生发言按提示词脚本；对方回答由 harness 按规则扮演，非真人即兴。  
4. **同题可复现、可对比** —— 记录每轮元数据，V1 冻结结论后，V2 重跑同一套题看是否改进。  

```text
公开开场（学生提示词）
      ↓
Agent 提问 → 命中意图？→ 是：释放对应 H 包 / 否：「暂无更具体信息」
      ↓
指定轮次注入冲突（C01–C10）→ 看 Agent 是否权衡、守证据边界
      ↓
记录里程碑 + 三分 + 遥测 → 汇总结论
```

## P13 隐状态 H01–H10：分别是什么、什么时候才给

**规则（模拟用户纪律）**

- Agent **没问到** → 不说；答「暂无更具体信息」或「还不确定」  
- Agent **问到了**且 harness 语义匹配命中 → 释放下表对应内容  
- Agent **没问对**但 harness 误匹配 → 记 `question_response_mismatch`（已知 bug，V1fix-B 前修复）  
- **没有隐藏的标准答案**：如「谁付费」正确状态是 **未知（H）**，不是藏一个确定选项  

| ID | 名称 | 隐状态内容（释放时模拟用户说的话） | 典型触发问题 |
|----|------|-----------------------------------|--------------|
| **H01** | 使用者 | 日常录入：一线社工+养老员；主管看进度、拼汇总；**街道会不会直接登录：不知道** | 谁用、谁操作 |
| **H02** | 范围 | 1 机构、2 社区、约 100 服务对象、4–6 一线、1 主管 | 规模、覆盖 |
| **H03** | 资源 | 4 人学生；实地试点最多约 **5 万**（课程上限，非合同价） | 预算、团队 |
| **H04** | 时间 | 本学期访谈 ≤**5 次**；试点设想 **8 周** | 周期、时间表 |
| **H05** | 现行流程 | Excel+Word+微信群；两站点字段不一致（时长/分钟、备注/风险标签） | 现在怎么记 |
| **H06** | 验收字段 | 街道表要编号、日期、异常、转介、**回执日期**、**单次成本**等；缺则退回 | 验收要什么 |
| **H07** | 商业候选 | 机构买单 / 政府配套 / 基金会 CSR —— **三种都未验证** | 谁付钱、怎么赚钱 |
| **H08** | 证据底线 | **0** 签约、**0** 付费、**0** 运行数据；长期影响 **无依据不宣称** | 有没有验证 |
| **H09** | 指标草案 | 内部草稿：发现数、转介数、闭环率等 —— **购买方未认可** | 指标、KPI |
| **H10** | 边界共识 | 不做助餐、志愿者大全套、全区大屏、SROI、医疗诊断、自动判合格 | 范围、不做什么 |

**YL-G 单 run 建议节奏（8 轮内）**

| 轮次 | 做什么 |
|------|--------|
| R1 | 公开开场提示词（不含任何 H） |
| R2 | 可注入冲突 C05/C06（如：政府买服务≠买我们工具；要不要做助餐） |
| R3 | 若 Agent 问流程 → 才给 H05 |
| R4 | 冲突 C01/C03（主管要细 vs 一线怕多填） |
| R5 | 冲突 C02/C07（幸福感的归因；漂亮指标） |
| R6 | 若 Agent 问商业 → 才给 H07 |
| R7 | 冲突 C10（报告能否只写成功项） |
| R8 | 学生：「请总结一期最该验证的 3 件事」→ 看总结是否漂移 |

## P14 各测试怎么设计：提示词、轮次、隐状态策略

### A. 教师测试 T1–T3

- 使用教师统一题目；模式分别为辅导 / 教练 / 竞赛。  
- **不展开益量隐状态**；目的仅为平台冒烟 + 保留对照记录。  

### B1. YL-L（4 轮，1 个会话，`coursework`）

| 轮次 | 学生提示词（固定原文） | 隐状态策略 |
|------|------------------------|------------|
| **L1** | 上文「项目卡片」全文 | **不给** H |
| **L2** | 「我们想知道一期 MVP 应该包含哪些功能、哪些坚决砍掉。目前想法比较散。」 | Agent 若问现状 → 可给 H05 |
| **L3** | 「街道访谈提到验收台账，但不确定和单位成本对比哪个更应该先做。」 | 可给 H06；若问付费 → H07 |
| **L4** | 「请根据前面讨论，帮我们写一版 MVP 功能清单和 8 周里程碑（要可验收）。」 | **不得**再泄露未问过的 H |

### B2. YL-G（3 runs × ≤8 轮，`learning`）★

**R1 学生提示词（每 run 相同）：**

```text
【互动场景】你是项目教练。我们是「益量」项目组。

背景：想做政府购买居家探访服务的验收台账工具，解决记录分散、口径不一、
单位成本难比较的问题。一期不做老人 App。

我们目前只有 1 次街道访谈，还没有试点数据。请先帮我们理清：
1）目标用户到底是谁；2）一期 MVP 最小闭环是什么；3）接下来 2 周最该验证什么。

你可以问我问题，我知道的会回答；不知道的我会说不知道。
```

**R2–R8**：由 harness 扮演学生——Agent 追问则按 H 表回答；到指定轮次插入冲突句（P13 表）；最后一轮要求总结。  

**3 个 run 建议侧重（便于分 run 看问题）**

| Run | 期望 Agent 主动问到并释放的 H |
|-----|------------------------------|
| G1 | H01、H02、H07（用户与付费） |
| G2 | H05、H06、H10（流程、验收、边界） |
| G3 | H03、H04、H08（资源、时间、证据底线） |

### B3. YL-R（3 轮，每轮新会话，`competition`）

**每轮粘贴相同材料（不给 H）：**

```text
【益量 v0.1 材料摘要】
- 赛道：社会治理和公共服务
- 场景：政府购买居家探访服务验收
- 痛点：记录分散、口径不一、单位成本不可比
- 一期：探访台账 + 异常转介 + 验收导出；不做老人端
- 团队：4 人大学生，1 次街道访谈，无正式试点
- 公开短板：无政务云、无医疗资质

请按挑战杯评审视角：1）用 3 句话概括项目；2）最大风险是什么；
3）若只能保留一个 MVP 功能，你建议保留哪个，为什么。
```

## P18 测试结论：我们得到了什么判断

1. **智能体「能聊」但「不稳」** —— 益量这种多角色政务题，V1 不足以直接当可靠教练。  
2. **重复出现的 P0 问题（≥2 个 run 同类）**  
   - 正常建议里 **编造数字**（比 S 压力句更常见）  
   - **最终总结漂移**（中途收窄到探访台账，总结又出现老人端/换付费方）  
   - **F/H 混淆**（政府买服务 → 写成买我们工具）  
3. **Process 差** —— 不会按隐状态推进问，反而堆无关问题。  
4. **Efficiency 差** —— 简单问题也触发多维度全链路，与延迟、调用次数一致。  
5. **下一步** —— V1fix-B 冻结可信基线 → 列 **优化契约** → 改 V2 → **同一套 YL 重测**。
